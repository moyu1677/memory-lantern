# 网页接入与数据保护

## 家人使用流程

```text
老人先完成自然聊天
    ↓
家人登录自己的已绑定账户
    ↓
在“家庭关怀报告”页选择对应老人并点击“根据近期聊天生成”
    ↓
后台调用提取模块、校验输出、保存概括性报告
    ↓
家人看到概括、类别和一项建议
```

家人不能直接输入聊天内容，也不能为未绑定的老人生成报告。

## 正式项目中的接入位置

本展示目录只放聊天关怀相关副本。正式网页的少量接入代码仍保留在原项目中，以免和其他模块的运行依赖脱节：

| 正式文件 | 聊天关怀报告相关职责 |
|---|---|
| `../app.py` | `/family-briefs` 页面、生成路由、管理员验证页；先检查家人—老人绑定关系 |
| `../database.py` | `care_reports` 数据表；保存报告；返回给家人时删除内部来源轮次 |
| `../templates/family_briefs.html` | 家人实际看到的报告页面，本目录已有副本 |
| `../templates/admin_care_report_validation.html` | 管理员查看实验汇总的页面，本目录已有副本 |
| `../validation/care_report_validation_latest.json` | 可公开的验证指标，本目录已有副本 |

## 保存什么，不保存什么

| 项目 | 是否保存 / 展示 | 原因 |
|---|---|---|
| 报告状态、概括、信号类别、建议、生成时间 | 保存并向已绑定家人展示 | 家人需要知道如何关心 |
| `source_turn_ids` | 仅在服务端短暂核验，不返回家人页面 | 防止内部证据被泄露或误解 |
| 聊天原话 | 不保存进关怀报告，不展示 | 保护老人隐私 |
| 未绑定老人的报告 | 不生成、不展示 | 权限隔离 |
| 验证集聊天原文 | 不写入公开验证结果 | 验证页只展示汇总指标 |

## 运行限制

当前网页从服务运行中的最近聊天会话读取内容。因此演示时应先让老人完成几轮聊天，再由已绑定家人在同一次服务运行期间生成报告。服务重启后，该内存会话会清空；已有的关怀报告仍会保留在数据库中。
