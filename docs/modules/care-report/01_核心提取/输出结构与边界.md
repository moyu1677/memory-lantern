# 输出结构与边界

## 输入是什么

输入仅是**同一段老人和 AI 已完成的对话中，老人自己说过的话**。

- 不读取老人和家人的聊天；
- 不读取其他老人的内容；
- 至少需要两轮老人表达，否则不生成报告；
- 系统只保留最近会话用于生成，家人不能凭空创建或拼接一段“聊天记录”。

## 输出是什么

模型只能输出下面这个固定结构，之后还要经过程序校验：

```json
{
  "status": "signals_present 或 insufficient_or_conflicting",
  "summary": "不给出诊断的简短概览",
  "signals": [
    {
      "area": "psychological 或 physical_or_daily",
      "topic": "简短关怀主题",
      "strength": "low 或 medium",
      "trend": "new、repeated、improved 或 conflicting",
      "family_action": "一句可执行的家人建议",
      "source_turn_ids": [1]
    }
  ]
}
```

其中 `source_turn_ids` 只在服务端用于核验“这条提示是否确实来自本次聊天”，**永远不显示给家人**。

## 只允许的两类信号

| 字段 | 给家人看的中文含义 | 例子（仅说明类别，不是诊断） |
|---|---|---|
| `psychological` | 心理与陪伴 | 想联系家人、需要陪伴、感到孤单、想参与活动 |
| `physical_or_daily` | 生活与身体 | 行动安全、睡眠、视听、日常自理、家务安全、身体不适 |

普通做饭、天气、兴趣爱好等日常描述本身不能被当作“生活与身体困难”。

## 程序强制做的保护

1. 拒绝疾病诊断、处方、用药调整和确定性心理结论；
2. 拒绝复制老人输入里连续 10 个及以上字符，避免把原话带到家人页面；
3. 只接受当前对话实际存在的来源轮次；
4. 最多保留 3 条提示；
5. 新近表达若明确说明“已经解决”“不用担心”“不需要帮助”，会覆盖更早的旧问题；
6. 线索不足、普通闲聊或前后矛盾时，必须返回 `insufficient_or_conflicting`，即“暂不形成关怀提示”。

## 本模块不做什么

- 不诊断抑郁、失智、阿尔茨海默病或其他疾病；
- 不给药物、就医或紧急处置指令；
- 不替家人解释老人全部内心想法；
- 不展示聊天原文；
- 不使用 MoCA 结果。本模块与认知测评模块的融合属于后续独立步骤。
