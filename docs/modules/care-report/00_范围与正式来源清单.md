# 范围与正式来源清单

## 结论

聊天关怀报告的**展示、测试、说明材料已经集中在本目录**。不过正式网页不能只靠本目录单独运行：`app.py` 和 `database.py` 是全站共用的入口，必须保留在项目根目录。这不是遗漏，也不是其他模块混入，而是为了不破坏当前网站。

## 本模块的正式运行来源

| 原项目文件 | 是否已在本目录集中展示 | 为什么原文件仍保留在外部 |
|---|---|---|
| `care_report_engine.py` | 是，见 `01_核心提取/` | `app.py` 运行时直接导入它 |
| `app.py` 的关怀报告路由 | 是，见 `02_家人页面/路由与存储代码摘录.md` | 同一文件还承载登录、聊天、语音等全站路由，不能只为本模块移动 |
| `database.py` 的 `care_reports` 表与读写函数 | 是，见同一代码摘录 | 同一文件管理全站数据库连接与其他表 |
| `templates/family_briefs.html` | 是，完整展示代码 | 网页运行时必须从正式模板目录读取 |
| `templates/admin_care_report_validation.html` | 是，完整展示代码 | 网页运行时必须从正式模板目录读取 |
| `static/app.css` 的报告专用样式 | 是，见 `care_report_styles.css` 摘录 | CSS 是全站共用文件 |
| `validation/care_report_validation_latest.json` | 是，完整副本 | 管理员网页运行时读取正式验证目录 |
| `tests/test_12_care_reports.py`、两个 benchmark 脚本 | 是，展示代码 | pytest 和测试目录需要保留既有结构 |
| 冻结案例、验证说明 | 是 | 原文件保留为可复现测试的正式来源 |

## 不属于当前聊天关怀报告模块的内容

| 文件或区域 | 实际用途 | 为什么不放进来 |
|---|---|---|
| `Moca模块/`、`questions.py`、`reports.py` | 认知测评、题目与认知报告 | 不是聊天报告，不能和本模块混合 |
| `asr_service.py`、`voice_service.py`、`remote_asr/`、`remote_tts/` | 语音识别、声音合成和声音克隆 | 它们是聊天的输入/输出能力，不负责提取和家人报告；且正由其他线程修改 |
| `needs_engine.py`、`need_cards` 表、`test_10_voice_chat.py` | 旧版“需求卡”流程，需要老人明确授权后保存卡片 | 与当前“无原话、自动生成关怀报告”的新流程不同，不能混为同一个功能 |
| `rag.py`、知识库页面、成语游戏 | 问答、知识与互动功能 | 与聊天关怀报告无关 |

## 验证归档的处理

原 `tests/results/` 里还保留多个时间点的原始运行记录。这些是过程归档，不是展示或运行所需文件；本目录保留了最终 holdout 案例、公开指标汇总和完整验证说明，足以复现和解释最终结果。最终 27 次运行的明细文件名已写在 `完整验证记录.md` 中。

因此，可以开始整理其他模块；聊天关怀报告不再需要和 MoCA、语音或旧需求卡一起重复归类。
