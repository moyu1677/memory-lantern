# 家庭关怀报告：最终验证结论

## 本次验证验证的是什么

验证的是这条工程链路能否工作：

```text
冻结合成多轮对话 → DeepSeek 提取 → JSON 安全校验 → 家人报告
```

它不验证真实老人群体的临床准确率，也不声称 AI 能读出老人所有真实需求。

## 真实模型调用结果

- 模型：`deepseek-v4-flash`，thinking enabled；
- 案例：9 个预先冻结的合成多轮对话；
- 每例独立运行 3 次，共 27 次真实 API 调用；
- 结果只保存案例编号、类别、通过情况和耗时，不保存测试聊天原文或模型原文。

| 指标 | 结果 | 如何理解 |
|---|---:|---|
| 合格结构化报告 | 27 / 27（100%） | 每次都产生可校验、可展示的结构化结果 |
| 明确关怀需求命中 | 10 / 12（83.3%） | 大多数明确需求可识别；轻度、含蓄协助需求仍可能漏报 |
| 无信号时正确克制 | 15 / 15（100%） | 普通闲聊、问题已解决、明确拒绝帮助时不会强行推送 |
| 状态与类别完全一致 | 24 / 27（88.9%） | 最严格地要求状态、类别都正确 |
| 三次运行完全稳定 | 7 / 9（77.8%） | 两个边界案例存在波动，不能隐瞒 |
| 平均模型生成耗时 | 3.40 秒 | 仅模型调用耗时，不含网页操作 |
| API 错误 | 0 | 27 次调用均完成 |

## 两个需要坦诚说明的边界

1. “小字表格看不清、希望家人核对”这一类轻度、含蓄的协助需求，有 2 次被保守地漏报。
2. “短暂头晕、希望家人知道”每次都被识别为生活/身体关注，但有 1 次额外出现了心理与陪伴类别。

所以，这个模块适合做**保守的联系提醒**：宁可在轻度线索上少提示，也不应把普通聊天或已解决的问题推送给家人。

## 已经跑通的端到端验收

- 老人连续发送 3 次真实聊天请求：均返回 HTTP 200；
- 已绑定家人可生成报告；
- 家人页面不出现测试聊天原话；
- 管理员可查看不含原话的验证汇总；
- 未绑定家人被 HTTP 403 拦截；
- 项目自动化回归：51 passed。
