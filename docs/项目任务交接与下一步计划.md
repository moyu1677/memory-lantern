# 忆路明灯项目任务交接与下一步计划

更新日期：2026-07-27

本文档用于记录当前代码状态、已经完成的工作、已知问题和后续优先任务。下一次开发开始时，应先阅读本文档，再查看相关源文件。

## 1. 项目当前目标

项目面向老年人的智慧陪伴和认知表现测试，当前核心目标包括：

- 提供适老化的大字、大按钮交互；
- 支持普通话、粤语和潮汕话语音输入；
- 提供适合老人的轻量语言互动小游戏；
- 通过固定规则完成认知任务评分；
- 保存用户和历史测试结果；
- 为老人、家属和社区提供分角色的查看与沟通能力；
- 控制隐私风险，不默认保存原始录音和完整回答。
- 提供有来源、可审核、按角色展示的本地健康知识中心。

测试结果仅用于项目演示和初步参考，不构成医学诊断。

### 2.2 语音输入与朗读

- 普通话使用浏览器 Web Speech API；
- 粤语使用腾讯云 `16k_yue`；
- 潮汕话使用腾讯云 `16k_zh_en`；
- 浏览器通过 `MediaRecorder` 录音；
- 后端使用 FFmpeg 转为 16kHz、16bit、单声道 PCM；
- 后端生成腾讯云 WebSocket 签名并按实时速度发送音频；
- AI 回复使用浏览器语音合成朗读；
- 粤语模式优先选择 `zh-HK` 系统声音。

相关文件：

- `templates/index.html`
- `app.py`
- `tencent_asr.py`

真实腾讯云调用已经验证：

- 静音录音能够成功调用，但返回空文本；
- 非静音测试语音通过同一链路能够返回文字；
- 因此当前主要问题是潮汕话模型准确率，而不是接口未调用。

### 2.3 认知表现测试

- 题库已扩充为62道题目变体；
- 包含即时记忆、延迟记忆、时间定向、注意力、计算能力、语言能力和日常判断；
- 每次测试按固定维度配额随机生成10题；
- 第一题与最后一题使用同一组随机词语，分别测试即时记忆与延迟记忆；
- 中间8道题随机排列，降低反复测试时记住题序的影响；
- 满分仍为14分，各维度最高分保持不变，兼容已有历史报告；
- 使用确定性规则评分；
- 测试过程中不立即提示对错；
- 测试结束输出总分、百分制表现和各能力维度；
- 明确提示结果不构成医学诊断；
- 测试完成后写入 SQLite；
- 不保存原始语音和完整回答。
- 保存题库版本和本次题目 ID，用于追踪随机试卷，但不保存用户原始答案。

## 3. 当前数据库结构

### 3.1 `users`

保存：

- 用户 ID；
- 唯一账号名称；
- 密码哈希；
- 显示称呼；
- `member` 或 `admin` 角色；
- 老人、家属、社区或后台管理员账户类型；
- 老人端专属绑定码；
- 启用状态；
- 注册时间；
- 最近登录时间。

### 3.2 `assessments`

保存：

- 唯一测试会话 ID；
- 用户 ID；
- 总分；
- 满分；
- 百分制表现；
- 反馈等级；
- 各维度得分 JSON；
- 输入语言；
- 随机题库版本；
- 本次抽取的题目 ID；
- 完成时间。

不保存：

- 原始录音；
- 完整识别文本；
- 每一道题的原始回答。

### 3.3 `care_bindings`

保存：

- 老人用户 ID；
- 家属或社区用户 ID；
- 绑定时间；
- 同一账户与同一老人只允许一条绑定关系。

### 3.4 `messages`

保存：

- 留言关联的老人；
- 发送者和接收者；
- 留言正文；
- 已读状态；
- 创建时间。

只有共同绑定同一老人的家属端和社区端可以互相发送留言。

### 3.5 `idioms`

保存：

- 成语正文；
- 首字和末字索引；
- 是否启用；
- 数据来源。

当前种子版本包含 29,536 条纯中文四字成语。`app_metadata` 表记录种子版本，确保升级时补充数据且不会重复导入。

### 3.6 `knowledge_articles`

保存文章标题、摘要、正文、分类、适用角色、关键词、关联能力维度、来源、作者、审核人、审核意见、草稿/待审核/已发布/退回/停用状态及时间。内置文章使用唯一 `slug` 和种子版本更新。

### 3.7 `knowledge_favorites`

保存用户与文章的收藏关系。同一用户对同一文章最多一条记录。

### 3.8 `knowledge_documents`

保存管理员导入文档的文档编号、标题、原文件名、提取正文、分类、适用角色、来源机构、来源链接、内容哈希、草稿/发布/停用状态、分块数量、上传者、审核者和时间。内容哈希用于拦截重复导入。

### 3.9 `knowledge_chunks`

保存已发布知识文章和文档的可重建检索分块，包括来源类型、来源 ID、内容哈希、分块序号、章节标题、正文、稳定分块编号和索引时间。该表是派生索引，权威内容仍在 `knowledge_articles` 和 `knowledge_documents`。

## 6. 当前已知问题

### 6.1 潮汕话识别错误率较高

当前使用：

```text
16k_zh_en（大模型1.0混合方言引擎）
```

接口可以正常返回文字，但对部分潮汕话说话人的识别准确率不稳定。

### 6.2 识别结果会自动提交

当前前端在收到腾讯云识别结果后执行：

```javascript
document.getElementById('user-input').value = data.text;
await sendMessage();
```

这意味着错误识别会直接进入认知测试评分，是当前最高优先级风险。

成语接龙已经采用“识别后先显示、用户确认后再提交”的方式，后续可以把同样的确认流程复用到认知测试。

### 6.3 大词库包含生僻成语

当前本地数据库已经扩充到 29,536 条四字成语，可以显著增加接龙路线，但其中包含部分生僻成语。后续可以增加“常用程度”字段，让电脑优先选择老年人更熟悉的成语，同时继续允许用户提交完整词库中的答案。

### 6.3 测试进行中的状态仍保存在内存

已完成结果保存在 SQLite，但进行中的题号和临时得分仍保存在：

```python
TEST_SESSIONS = {}
```

Flask 进程重启后，尚未完成的测试会丢失。

### 6.4 SQLite 没有正式迁移工具

目前启动时使用 `CREATE TABLE IF NOT EXISTS`。后续修改字段时需要迁移机制，不能依赖删除数据库重建。

### 6.5 当前使用 Flask Debug Server

`app.py` 末尾仍为：

```python
app.run(debug=True, port=5000)
```

只能用于本地开发。

### 6.6 管理功能仍是原型

尚未实现：

- 用户自行修改密码；
- 忘记密码或短信验证；
- 登录失败频率限制；
- 操作审计日志；
- 家属与老人账号绑定；
- 数据导出和授权撤销。

### 6.7 评分标准不是临床量表

当前问题、得分和反馈阈值为项目原型。正式用于筛查前，必须由医学或心理专业人员审核。

### 6.8 知识库审核仍是原型

当前搜索使用 SQLite `LIKE`，适合本地小型文章库；文章增多后需要专用全文索引。管理员审核依赖人工核验，目前没有双人复核、来源失效检查、文章版本回滚和操作审计。社区投稿也尚未提供删除、撤回和附件功能。

## 7. 下一步任务优先级

## P0：识别结果确认流程

目标：任何云端识别结果都不能直接参与认知测试评分。

建议界面：

```text
我听到的是：今天星期三

[确认并提交] [修改文字] [重新说一次]
```

实施要求：

- 删除云端识别完成后的自动 `sendMessage()`；
- 把识别文字放入确认卡片或输入框；
- 用户确认后才提交；
- 支持重新录音；
- 测试模式和普通聊天模式都使用同一确认流程；
- 不把“用户修改后的答案”当成模型识别准确率数据，统计时应区分。

## P0：腾讯云大模型2.0 A/B 对比

腾讯云最新实时引擎：

```text
16k_zh_en_2.0
```

它使用实时语音识别 V2 协议，不能只修改引擎字符串，需要：

- 新增 V2 WebSocket 客户端；
- 保留当前1.0作为回退；
- 在开发配置中增加1.0/2.0切换；
- 使用同一批真实潮汕话样本进行对比；
- 记录整句准确率、关键词召回率、数字和日期识别率；
- 确认计费方式后再设为默认。

## P1：建立潮汕话测试集

建议：

- 3至5位母语或长期使用者；
- 每人10至20句；
- 覆盖慢速、正常语速、老人声音较小等情况；
- 人工标注正确文本；
- 不上传姓名、地址等身份信息；
- 明确录音授权和删除时间。

## P1：安全的文本规范化

评分前统一：

- 简体和繁体；
- 中文数字和阿拉伯数字；
- 星期、周、礼拜；
- 常见粤语或潮汕话表达；
- 合理同义词。

不要使用 DeepSeek 静默改写评分答案，避免判分标准漂移。

## P1：热词与自学习模型

普通聊天可以尝试地名和常用词热词。

认知测试中不要直接把正确答案设置成高权重热词，否则识别模型可能偏向标准答案，造成分数虚高。

收集到足够且已授权的真实语料后，再评估腾讯云自学习模型。

## P1：测试进度持久化

把进行中的测试状态迁移到数据库：

- 当前题号；
- 临时总分；
- 各维度临时得分；
- 开始时间；
- 状态；
- 测试会话 ID。

这样服务重启后可以继续未完成测试。

## P1：正式数据库迁移与备份

- 引入 Flask-Migrate/Alembic，或制定 SQLite 手工迁移脚本；
- 部署时切换到 MySQL 或 PostgreSQL；
- 设置定期备份；
- 测试恢复流程；
- 规定用户数据保留和删除期限。

## P2：知识库语义检索与审计增强

当前本地中文片段检索已可用于原型。资料量显著增大后再评估：

- 采用本地或受控部署的中文向量模型增加语义召回；
- SQLite 继续作为权威内容源，向量索引只作为可重建派生数据；
- 建立命中文档 ID、文档版本、模型名称和回答时间的最小化审计记录；
- 增加来源链接失效检查、文档版本回滚和双人复核；
- 用脱敏问题集测试召回率、错误引用率和“无依据时拒答”表现；
- 不记录无必要的老人原始提问，不把未审核稿件送给外部模型。
