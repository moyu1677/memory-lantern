# 机器辅助绘图评分说明

更新时间：2026-08-07

## 1. 当前实现到什么程度

项目现已具备一条完整、可运行的研究型数据链路：

1. 老人端在 `/drawing-lab` 使用鼠标、触屏或触控笔完成绘图；
2. 浏览器记录图片、笔画坐标、相对时间和压力值；
3. 服务端提取笔画数、轨迹长度、覆盖范围、闭合笔画比例等可解释特征；
4. 如果 `data/models/` 中存在对应模型，则生成机器辅助预测；
5. 没有模型或预测置信度低于阈值时，系统明确显示“等待人工复核”；
6. 管理员在 `/admin/drawings` 完成人工复核；
7. 两名独立评分者得分一致后形成训练标签；不一致时必须由未参与初评的第三人仲裁；
8. 只有取得研究同意并形成共识/仲裁标签的样本才能导出或训练；
9. 原有14分生活化测试不读取绘图结果，两个体系不混算。

因此，当前已经实现“机器评分的工程基础”，但刚安装完成时还没有经过训练的模型，
不能把页面输出称为可靠的自动量表评分，更不能据此诊断认知障碍。

## 2. 代码和数据位置

- `drawing_scoring.py`：轨迹清洗、特征提取、模型训练、预测和低置信度拒判；
- `tools/train_drawing_model.py`：从 SQLite 中读取已形成共识的样本并训练模型；
- `templates/drawing_lab.html`：老人端绘图采集；
- `templates/admin_drawings.html`：管理员复核队列；
- `templates/drawing_review.html`：独立评分与仲裁；
- `database.py` 中的 `drawing_submissions`：图片、轨迹、特征、同意状态和机器预测；
- `database.py` 中的 `drawing_reviews`：评分者、角色、量表要点、得分和备注；
- `data/models/drawing_trail.json`、`drawing_cube.json`、`drawing_clock.json`：训练后生成的模型。

SQLite 数据库、真实绘图与老人信息不会提交到 Git。

## 3. 如何完成第一轮数据收集

1. 确认使用的量表版本、电子化范围和素材已经取得书面授权；
2. 准备受试者信息说明、知情同意和退出/删除流程；
3. 尽量使用统一的屏幕尺寸、触控笔/鼠标和浏览器版本；
4. 每份绘图由两名经过同一评分培训的人员独立评分；
5. 两人不得在初评前查看对方得分，也不应先看机器预测；
6. 分歧由第三名未参与初评的人员仲裁；
7. 数据集按“受试者”划分训练集、验证集和测试集，禁止把同一人的不同绘图拆到不同集合；
8. 保留一批完全不参与训练的外部测试样本。

训练脚本默认每个得分类别至少5份样本，这只是为了防止程序在极少数据下启动，
不是临床有效性或论文可信度的样本量标准。正式研究需要根据预期效应、类别分布、
设备差异和统计方案进行样本量估计，并由导师或统计人员审核。

## 4. 训练模型

先在后台完成足够的双人复核，然后运行：

```powershell
python tools/train_drawing_model.py --task all --minimum-per-class 5
```

也可以只训练一个任务：

```powershell
python tools/train_drawing_model.py --task clock --minimum-per-class 5
```

脚本会：

- 忽略未同意用于研究的样本；
- 忽略只有一名评分者或两人意见不一致且尚未仲裁的样本；
- 为每种任务生成独立模型；
- 写入特征版本、训练时间、各类别样本量和模型指纹；
- 样本不足时停止训练，不会伪造模型。

重启 Flask 后，新提交的绘图会自动加载对应模型。默认置信度阈值为0.75，可在
`.env` 中设置：

```text
DRAWING_MODEL_DIR=data/models
DRAWING_CONFIDENCE_THRESHOLD=0.75
```

阈值不能只为了“多给结果”而降低，应在独立验证集上根据错误成本确定。

## 5. 匿名导出

管理员可在绘图复核页面点击“导出已形成共识的数据”。CSV只包含：

- 随机样本号；
- 任务类型；
- 共识/仲裁得分；
- 标签来源；
- 特征版本与数值特征。

CSV不包含姓名、账号、原始图片和笔画坐标。如果研究确实需要原图，应另外设计
受控导出、加密存储、访问日志和到期删除机制，不应通过 Git、群聊或普通网盘传输。

## 6. 什么时候才能说“实现机器评分”

可以分成三个口径：

- **工程演示口径：** 已达到。系统可以采集、训练、预测、拒判并转人工复核；
- **研究实验口径：** 还需要真实双人标注数据、按受试者划分的测试集、准确率/
  加权Kappa/混淆矩阵/校准度和设备分层结果；
- **临床使用口径：** 当前没有达到。还需要量表授权、伦理审批、目标人群验证、
  医疗与法规评估、人工监督和持续质量管理。

系统展示时建议使用“机器辅助评分研究原型”，不要使用“AI诊断”或“自动判断老人
是否患认知障碍”等表述。

## 7. 下一步建议

1. 先用团队成员制作的非临床模拟样本验证页面和复核流程；
2. 请量表培训人员审核页面指令和每个评分要点；
3. 增加评分者盲法、评审账号审计与删除日志；
4. 收集第一批合规样本并报告评分者间一致性；
5. 把当前最近质心模型作为论文基线，与逻辑回归、随机森林或轻量视觉模型比较；
6. 独立测试后再决定置信度阈值，并保留“拒绝自动给分”的路径；
7. 任何模型升级都保留旧模型版本和对应测试结果，不能覆盖历史记录。
