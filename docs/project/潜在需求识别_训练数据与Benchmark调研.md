# 潜在需求识别：训练数据与 Benchmark 调研

> 更新：2026-08-07
> 当前聊天模块的目标：从一段或多段老人—AI 聊天中，预测老人最希望家人理解、但未必直接说出口的**潜在需求**，并按重要性排序。
> 这不是普通摘要，也不要求聊天卡向家人展示老人原话。
>
> **指标更正（2026-08-07）：** “排序”不是当前产品的默认核心。当前建议先让系统只判断“一个最主要的潜在需求 / 暂无足够判断”，以分类准确性为主指标；只有后续真的要向家人同时呈现多个需求时，才启用排序与 NDCG 等指标。

---

## 1. 任务到底是什么

普通摘要回答“老人说了什么”。

本项目要回答的是：

> 老人在这些聊天背后，最希望得到什么样的家庭支持？其中最重要的是哪一件？

```text
连续多轮老人—AI 对话
          ↓
潜在需求分类 + 优先级排序 + 置信度
          ↓
家人端提示：近期可能最需要更多联系与陪伴
```

例如，老人连续几次谈到“饭做多了”“电视也没意思”，模型的目标不是逐句摘录，而是把“希望有人联系/陪伴”排到较前位置。

这里的核心关键词是 **latent need inference（潜在需求推断）**。当前版本的输出只需要是“最主要的潜在需求”，不是开放式摘要，也不必一次列出许多需求。

---

## 2. 从大量聊天中准确提取真实需求，能不能做到？

**能做成概率预测模型，但绝不能在没有标签的情况下证明它真的读懂了老人。**

模型能通过大量聊天学到“某类表达组合通常对应某类需求”。但“老人真正最想要什么”不是对话文本天然附带的标准答案。要训练或验证，数据必须成对存在：

| 模型看得到 | 模型看不到、但用于训练/验证的真值 |
|---|---|
| 多轮聊天 | 参与者事后确认的需求排序 |
| 多轮聊天 | 研究场景预先设定的隐藏需求 |
| 多轮聊天 + 独立生活支持评估 | 专业人员或双评审给出的需求排序 |

如果只有很多聊天、没有右边的标签，最多可做主题发现或聚类，不能计算“准确率”。

如果人工评审、人工打标和真实需求访谈都不可行，就不能把结果称为“真实需求准确率”。此时应切换为下文的**自动化行为测试**：验证模型面对可控变化时是否保持应有行为，而不是虚构一份不存在的人工金标准。

当前最稳妥的任务定义是：

```text
聊天历史 → [陪伴、被理解、复诊协助、用药协助、出行协助……] 中的一个主需求，或“暂不判断”
```

如果未来的产品确实要同时显示“主要需求 + 次要需求”，再把这一定义扩展成排序任务。

## 3. 公开数据调研结果

### COCOON：最贴近“从含糊表达发现潜在需求”的中文研究

**论文：** Fu et al., *Look Beyond Feeling: Unveiling Latent Needs from Implicit Expressions for Proactive Emotional Support*，EMNLP 2025。
论文：[ACL Anthology](https://aclanthology.org/2025.emnlp-main.1094/)；代码：[官方仓库](https://github.com/xingqwq/COCOON)。

这篇论文研究的问题与你的聊天模块最接近：用户不愿直接说情绪和需要，系统应通过不冒犯的主动倾听逐步识别隐含需求，而不是靠大量追问。

| 项目 | 论文中的情况 | 对我们有何价值 | 局限 |
|---|---|---|---|
| 语言 | 中文 | 可直接参考中文多轮对话处理 | 不是老人专用语料 |
| 对话规模 | 约 3,500 段、多轮 | 可用作潜在心理需求的模型/提示词参考 | 不覆盖家庭照料的全部需求 |
| 任务 | 主动情感支持、隐含需求发现 | 与“老人未直接开口”的心理需求相近 | 不能验证身体、出行、用药等需求 |
| 数据来源 | 初始对话按脚本由 GPT-4o 生成，后续筛选和细粒度标注 | 可作受控训练/对比材料 | **不是老人真实生活对话真值集** |

结论：COCOON 是目前最值得引用的“潜在需求”方法论文，但只覆盖**心理支持**的一部分，且不能代替真实老人验证。

### ESConv：成熟情感支持 benchmark，但不等于老人需求 benchmark

**论文：** Liu et al., *Towards Emotional Support Dialog Systems*，ACL 2021。
论文：[arXiv](https://arxiv.org/abs/2106.01144)；数据与代码：[清华 COAI 官方仓库](https://github.com/thu-coai/Emotional-Support-Conversation)。

ESConv 含约 1,300 段英语情感支持对话，带支持策略、问题主题和使用者反馈。

| 可借用 | 不可借用 |
|---|---|
| 如何评估陪伴对话是否更有安慰性、是否问得过多 | 中文老人日常聊天训练集 |
| 心理陪伴类的对比 baseline、失败样本 | 身体、用药、出行等生活支持的真值 |
| 支持策略与满意度的评估方法 | “老人真正最想要什么”的金标准 |

### SeniorTalk：真实中国高龄老人语音，但没有潜在需求标签

**论文：** Chen et al., *SeniorTalk: A Chinese Conversation Dataset with Rich Annotations for Super-Aged Seniors*（2025）。
论文：[arXiv:2503.16578](https://arxiv.org/abs/2503.16578)；数据：[BAAI / Hugging Face](https://huggingface.co/datasets/BAAI/SeniorTalk)。

SeniorTalk 是真实中国 75–85 岁老人自然对话数据：101 段会话、202 位参与者、55.53 小时语音，包含人工转写、口音、地区、说话人等标注。

| 能用来做什么 | 不能用来做什么 |
|---|---|
| 检验老人语音识别、口音、停顿和转写质量 | 训练潜在需求分类/排序器 |
| 让系统适应真实老人说话方式 | 验证模型知道老人真正需要什么 |
| 作为 ASR 外部验证依据 | 直接生成家庭关怀标签 |

数据需要申请，页面写明学术非商业用途通常需 3–5 个工作日处理。所以它可作为项目的老人语音依据，但不应成为短周期实验唯一依赖。

## 4. 最关键的调研结论

目前找不到一个公开数据集同时满足：

1. 真实中国老人的长期日常聊天；
2. 多轮对话；
3. 每位老人事后确认的“真正想要什么”及优先顺序；
4. 同时覆盖心理陪伴与日常生活/身体支持。

所以没有一个可以直接下载、直接训练、然后宣称“模型准确读懂老人真实需求”的权威金标准。

这不是项目做不下去，而是要采用三层数据逻辑：

| 层 | 数据 | 它证明什么 |
|---|---|---|
| 老人语音层 | SeniorTalk 或授权老人语音 | 系统能否听懂老人 |
| 隐含心理需求层 | COCOON、ESConv | 系统能否学习/比较隐含需求和情感支持方法 |
| 项目核心层 | 自建、带真实需求排序标签的冻结集 | 系统能否把这个项目定义的需求排对顺序 |

公开数据补“技术能力”，自建冻结集验证“项目真正要解决的问题”。把不匹配的外部数据强套进来，反而比明确说明边界更不严谨。

## 5. 训练集 / 验证集的正确结构

每条样本至少应有：

```json
{
  "conversation_window": "模型可见的连续多轮聊天",
  "latent_need_labels": [
    {"need": "更多陪伴与联系", "priority": 1},
    {"need": "协助安排复诊", "priority": 2}
  ],
  "label_source": "场景预设 | 参与者事后确认 | 独立访谈/评审",
  "reference_moca": "如有，仅作为认知支持背景",
  "model_must_not_see": "latent_need_labels 和 label_source"
}
```

### 标签从哪里来

| 来源 | 对“真实需求”的价值 | 适合做什么 | 局限 |
|---|---|---|---|
| 预先设定的情境和隐藏需求 | 场景真值明确 | 开发集、冻结测试集 | 不等同于真实老人 |
| 老人试用后一次性说明最希望家人了解的事 | 最接近个人真实需要 | 小规模真实验证 | 只用于研究，不能成为日常产品负担 |
| 独立研究者访谈 + 家属/照护者补充 | 可覆盖复杂生活支持 | 真实试点的标签来源 | 要记录分歧和同意范围 |
| 只根据聊天倒推 | **不能当真值** | 探索性主题分析 | 会变成模型用自己的话证明自己 |

这里“事后一次性说明”是实验验证步骤，不是让老人每次看到聊天卡都确认。它不会改变你们产品的低负担设计。

## 6. 当前应该怎样测：先测分类，不把排序当主角

| 指标 | 来源/性质 | 它回答的问题 | 当前是否使用 |
|---|---|
| Macro-F1 | 标准多分类指标 | 各需求类别是否都能识别，而非只擅长陪伴类？ | **主指标** |
| Precision / Recall | 标准分类指标 | 模型报出的主需求有多少是对的；真实需求有多少被找出？ | **主指标** |
| Cohen's Kappa | Cohen 1960 的评审一致性统计量 | 两位人工标注者对“这段聊天的主需求是什么”是否本来就能达成一致？ | **主指标** |
| 误报率 | 项目安全指标，不是临床标准 | 不该推送需求时，系统却强行给出主需求的比例 | **主指标** |
| Top-1 / Recall@3 / NDCG@3 | 信息检索与推荐系统的标准排序指标 | 多个真实需求同时存在时，模型是否把重要的排在前面？ | 仅未来扩展使用 |

前四项已经足够支撑课程项目：先证明“人工之间能相对稳定地定义主需求”，再证明“模型对这个定义的识别效果超过基线”。

Top-1、Recall@K 和 NDCG 不是本项目自创：它们来自信息检索/推荐任务；NDCG 的经典出处是 Järvelin 与 Kekäläinen 的 2002 年论文。但如果产品并不展示多个排序后的需求，使用它们反而会让评价偏离问题本身。

### 6.1 无人工标注时的可行替代：自动化行为测试

这条方法借鉴 Ribeiro 等人在 ACL 2020 提出的 **CheckList**：不依赖逐条人工标注，而是先定义系统必须满足的行为关系，再自动生成大量改写或反事实测试。[CheckList 原论文](https://aclanthology.org/2020.acl-main.442/)

它不要求为每段聊天找人工评审。只需要团队**一次性定义需求类别和测试规则**；这属于产品规则设计，不是对大量聊天逐条打标。

| 自动测试类型 | 自动生成的对话变化 | 系统应该有的行为 | 可自动统计的指标 |
|---|---|---|---|
| 同义稳定性 | “一个人在家闷”改写成“最近家里太安静了” | 主需求判断不应无故改变 | 一致通过率 |
| 信息累积 | 同一信号出现 1 次、2 次、3 次 | 重复出现时置信度可上升，类别不应跳变 | 单调性通过率 |
| 反事实敏感性 | “孩子很久没联系”改成“孩子每天都会来” | 陪伴提示应减弱或消失 | 反事实通过率 |
| 不确定性/拒答 | 天气、新闻、普通闲聊等中性对话 | 输出“暂不判断”，而非强行给需求 | 正确拒答率 |
| 安全边界 | 普通疲劳、轻微不适、明确急性风险等模板 | 不诊断；高风险时只提示联系家人/专业机构 | 安全规则通过率 |
| 提示词鲁棒性 | 同一对话使用 3 种等价提示词 | 主需求不应因提示措辞大幅改变 | 提示词稳定率 |

测试中的“正确行为”由模板关系给定，例如“把每天联系改成长久未联系后，陪伴提示应加强”。无需让人工逐条阅读、逐条标注真实聊天。

它的边界也必须说清：**行为测试能证明系统行为稳定、不过度推断、会在不确定时克制；不能证明它已经准确读懂所有真实老人的内心。**

### 6.2 不应采用的伪替代

| 做法 | 为什么不够 |
|---|---|
| 让另一个 LLM 给模型打分 | 两个模型相互评价，不等于真实需求真值；只能作开发时辅助检查 |
| 让同一模型多跑几次并取多数票 | 可作为低置信度拦截信号，但多数一致也可能一起错 |
| 直接把 MoCA 分数当聊天需求标签 | MoCA 只覆盖认知筛查，不代表陪伴、生活帮助或身体主诉需求 |
| 用大量未标注聊天训练 | 只能学习语言模式，不能监督“主需求”是否正确 |

因此，当前家人端只显示“近期可能最需要：更多联系与陪伴”，或“当前聊天不足以判断”。无需向家人展示原话，也无需让模型强行给出第二、第三个需求。

## 7. 适合项目的技术选择

不建议在短周期内用少量真实样本从零训练一个“读心模型”。这会过拟合，也没有可信的泛化结论。

更合理的是：

```text
最近若干次聊天聚合
       ↓
中文大模型 + COCOON 的潜在需求方法参考
       ↓
固定需求集合中的主需求分类 + 置信度
       ↓
低置信度不强推；高优先级结果进入家人端
       ↓
在冻结的带真值案例上计算 Macro-F1、Precision、Recall、误报率
```

真正的创新不在于声称 AI “读心”，而在于把这个模糊问题变成有明确监督信号的排序任务：

> 在预先定义的家庭关怀需求集合中，模型能否识别出最主要的一项，且在没有足够信息时不过度推断？

---

## 8. 对外可用的一句话

> 系统基于多轮语音互动，预测老人最主要的潜在家庭关怀需求。我们借鉴公开的隐含需求与情感支持对话研究，并在带独立标签的冻结案例中，用 Macro-F1、Precision、Recall 和误报率验证结果。

不要说“AI 能准确知道老人内心真正想要什么”；更严谨的是“AI 预测潜在需求，并在独立标签集上衡量预测是否正确”。
