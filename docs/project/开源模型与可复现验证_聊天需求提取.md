# 聊天需求提取：模型能力与可复现验证（历史初稿）

> 本文只解决一件事：在**不假装能读懂老人所有心思**的前提下，怎样选择一个可用的开源模型，并用公开论文和可复现实验说明它为什么值得用。
>
> 结论先说：本项目不训练一个“能诊断老人、判断真实内心”的模型；聊天模块采用 **Qwen3-8B** 做受约束的信息提取与需求假设生成，先用公开基准和自动化行为测试验证，再接入家庭报告。它给出的是“值得家人留意的关怀信号”，不是诊断结果、心理结论或事实保证。
>
> **2026-08-09 更新：本机硬件与现有 API 核对后，上述“Qwen3-8B 为主模型”的结论已被 [现有 API 与本地模型对比_聊天需求提取.md](现有%20API%20与本地模型对比_聊天需求提取.md) 取代。当前主方案为仓库已接入的 `deepseek-v4-flash` API；Qwen3-8B 仅作本地备选。下文的任务边界、COCOON 局限与评测方法仍然有效。**

## 1. 我们到底要模型做什么

老人只和 AI 聊天，系统读不到老人和家人的真实私聊。因此模型的输入只能是经同意保存的老人—AI 对话文本（由语音识别得到）。模型输出也不能写成“老人一定患病”或“老人一定需要什么”，而应是两个方向的**关怀线索**：

| 方向 | 可以输出 | 绝不能输出 |
|---|---|---|
| 心理/关系 | 近期是否反复出现孤单、想被联系、对某件事失去兴趣、希望被理解等信号；建议家人如何开启一次真实交流 | “已患抑郁症”“真实想法就是……” |
| 身体/生活 | 对话中是否反复提到睡眠、疼痛、行动、吃药、跌倒、记忆或日常自理困难；建议家人关心或在持续/加重时咨询专业人员 | 疾病诊断、处方、替代医生判断 |

这不是“从一句话猜答案”。一次报告需要同时看：

1. 最近若干次会话的原始文本；
2. 每次会话中已抽出的客观信号；
3. 同一信号是否跨会话重复、是否有更近的相反表述。

原始对话只在系统内部用于复核；给家人的卡片不展示老人原话，也不要求老人逐条确认。系统内部仍保存来源会话/轮次编号，以便程序检查每条输出是不是有对话依据——**来源编号不是给家人的“原话卡片”**。

## 2. 模型选择结论

### 2.1 选用：Qwen3-8B（主模型）

推荐本地部署 `Qwen/Qwen3-8B`，原因不是它“万能”，而是它在本项目必须的条件上都满足：

| 条件 | 证据与项目意义 |
|---|---|
| 可开源、可本地部署 | 官方仓库说明开放权重采用 Apache-2.0；模型卡也标注 Apache-2.0。可用 Transformers、vLLM、SGLang、Ollama 或 llama.cpp 部署。 |
| 中文、多轮对话 | Qwen3 官方模型卡明确支持 100+ 语言/方言，并将多轮对话和指令遵循列为重点能力。它不是“医疗模型”，所以只承担语言理解与结构化提取。 |
| 足够的上下文 | 原生 32,768 tokens；官方提供 YaRN 扩展到 131,072 tokens 的方法。项目日常报告不应硬塞百万字历史：保留最近原文 + 更早的结构化会话摘要即可，32K 已够做当前版本。 |
| 可控成本 | 8B 是可落地的中等尺寸。相比 72B/235B，不需要把“很大”当成项目可靠性的前提；相比 1B/3B，小模型更容易在隐含语义和多轮矛盾上失真。 |

官方来源：

- [Qwen3 官方仓库与 Apache-2.0 许可说明](https://github.com/QwenLM/Qwen3)
- [Qwen3-8B 官方模型卡（8.2B、32K 原生上下文、131K YaRN、本地部署方式）](https://huggingface.co/Qwen/Qwen3-8B)
- [Qwen3 Technical Report（Yang et al., 2025）](https://arxiv.org/abs/2505.09388)

### 2.2 不直接采用：COCOON-Llama3

COCOON 论文非常贴近“从含糊表达中寻找隐性情绪需要”这个思路：它以主动倾听为框架，避免连续追问，试图由情绪—感受—需要链得到更深层的需要。这正好支持我们“不要让老人填问卷、不要逼老人确认卡片”的设计。

但不能直接把它当作项目最终模型，理由也必须写清楚：

1. 它只覆盖**情绪支持**，不覆盖身体、生活安全或药物相关线索；
2. 论文的 COCOON 对话由 GPT-4o 构造，平均约 18.82 轮，和长期真实老人—AI 对话有明显分布差异；
3. 截至 2026-08-08，作者公开 GitHub 仓库可见的是 prompt/eval/yaml 代码目录，未见可直接下载的完整训练/测试对话数据或权重。因此不能诚实地声称“我们已在它的公开 test set 上验证”。

所以它在本项目中的角色是：**方法论文依据**，不是未经验证直接上线的专家模型，也不是用来微调 Qwen3 的训练集。

- [COCOON 论文（Fu et al., EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.1094/)
- [COCOON 官方代码仓库](https://github.com/xingqwq/COCOON)

### 2.3 不在本阶段训练/微调

没有“真实老人长对话 → 后续确认的真实心理/身体需要”这种对口标签，就不应该为了显得有 AI 而拿合成情绪数据微调。那会把模型训练成擅长回答合成样本，不会证明它更懂项目里的老人。

因此本阶段是 **零样本/提示词 + 受约束输出**。后续若真正取得伦理合规、明确授权且有独立真实结果的数据，才重新讨论微调；这不是本项目当前的必要任务。

## 3. 实现路径：不是“每句话都嵌入隐空间”

这里不需要建立每句话的向量组合，也不靠相似度把一句话定性。

```text
语音 → ASR 文本 → 一次会话的短期信号表
                         ↓
最近原始会话 + 旧的会话级信号/趋势
                         ↓
Qwen3-8B 输出固定 JSON
                         ↓
程序校验 JSON、来源编号、矛盾和安全边界
                         ↓
给家人的“关怀提示报告”
```

### 3.1 两次任务，不是两个模型

仍然只用 Qwen3-8B，但把任务拆开，减少一次提示词既聊天又推理又写报告造成的遗漏：

| 阶段 | 输入 | 输出 | 目的 |
|---|---|---|---|
| 会话信号提取 | 一次会话原文 | `时间/活动变化/身体不适/情绪状态/关系线索/否定或矛盾/来源轮次` | 尽量不遗漏**已说出的事实线索**；不推断疾病或最终需要 |
| 报告级需求假设 | 最近原文 + 多次信号表 | 最多 1–3 条“值得留意的心理/生活/身体关怀信号”、强度、理由类型、家人建议、`unknown` | 对跨会话模式做谨慎解释；信息不足时明确不下结论 |

第二阶段必须重新看到相关原文，不能只看第一阶段的摘要。这样“提取器漏了一条”不会自动变成永久遗漏；而较早会话可保留会话级结构化记录，不必无限保存或嵌入每句话。

### 3.2 固定输出结构与硬边界

每次调用要求 JSON Schema，例如：

```json
{
  "signals": [
    {
      "category": "sleep_or_daily_function",
      "polarity": "present|denied|uncertain",
      "source_turn_ids": [3, 7],
      "time_scope": "recent|historical|unknown"
    }
  ],
  "care_hypotheses": [
    {
      "kind": "psychological|physical_or_daily",
      "status": "signal_present|insufficient_or_conflicting",
      "family_action": "..."
    }
  ],
  "diagnosis": null
}
```

程序而不是模型负责四个硬规则：

1. JSON 解析失败就重试/拒收，不能把自由文本直接入报告；
2. 输出项目外的疾病名、处方或确定性断言时拒收；
3. 每个信号必须带系统内部来源轮次；没有来源不得展示；
4. 输入相互矛盾或证据不足时只能给 `insufficient_or_conflicting`，不生成强结论。

这利用的是“受约束解码”来保证**格式合规**，不是误称“格式正确就语义正确”。[JSONSchemaBench](https://arxiv.org/abs/2501.10868) 专门指出，结构输出应分开评估约束覆盖、效率和任务质量；格式正确不等于内容正确。

## 4. 可复现实验：分别证明不同能力

没有一个公开分数能直接证明“模型理解了所有老人真实需求”。因此不能只报一个总分。下面四类实验分别回答四个不同问题，均可自动运行，不需要对真实老人聊天进行人工逐条标注。

| 要证明什么 | 公开基准/论文 | 我们如何使用 | 指标 | 能说明什么 / 不能说明什么 |
|---|---|---|---|---|
| 长对话里能否保留关键上下文 | [LongBench（ACL 2024）](https://aclanthology.org/2024.acl-long.172/)；[LongBench v2 代码/数据](https://github.com/THUDM/LongBench)；[RULER（Hsieh et al., 2024）](https://github.com/NVIDIA/RULER) | Qwen3-8B 与一个较小开源基线（如 Qwen3-4B）跑同一固定子集 | LongBench task score；RULER 各长度准确率 | 证明模型的长上下文读取能力；不证明它知道老人真实需要 |
| 能否从长期对话推断未直说的偏好/属性 | [PrefEval（Zhao et al., 2025）](https://huggingface.co/datasets/siyanzhao/prefeval_implicit_persona) | 用其 `implicit persona` 子集，优先跑不依赖闭源裁判的 classification 任务 | 分类准确率 | 与“从聊天形成个性化理解”最接近的公开自动测试；语料主要不是中文老人对话，所以只能作迁移证据 |
| 输出能否稳定进入程序 | [JSONSchemaBench（Geng et al., 2025）](https://github.com/guidance-ai/jsonschemabench) | 先测试本项目 JSON Schema 的 100 次生成；如算力允许再跑该公开基准子集 | JSON Schema 合规率、解析成功率、重试率 | 证明系统不会因格式崩坏而乱入库；不证明内容为真 |
| 是否存在明显漏读/幻觉/过度推断 | [CheckList（Ribeiro et al., ACL 2020）](https://aclanthology.org/2020.acl-main.442/) | 按论文的“行为测试”思想，生成固定、可自动判定的中文会话对 | 下节六项通过率 | 证明在预设风险场景中行为可控；不等于真实世界召回率 |

### 4.1 项目自身的无人工标注行为测试

这不是训练数据，也不是让人去给老人聊天打标签；它是像单元测试一样的固定输入—固定预期行为。每项 20–30 个变体即可，足以在项目展示中说明模型不是随便编结论。

| 测试 | 输入变化 | 自动判定 | 失败意味着什么 |
|---|---|---|---|
| 线索保留 | 在大量天气、家常等无关聊天中插入一次明确生活困难线索 | 应提取该类信号且保留来源轮次 | 关键信息被长上下文淹没 |
| 无关扰动不变性 | 在同一对话前后加口头禅、ASR 标点错误、无关闲聊 | 关怀类别不应改变 | 输出过度受表面措辞影响 |
| 矛盾处理 | 先提到连续失眠，后明确否认或说明已经好转 | 只能输出“存在矛盾/需留意”，不能高强度结论 | 模型只抓旧线索、忽略反证 |
| 无信号低误报 | 中性日常聊天，没有心理/身体困难 | `care_hypotheses` 应为空或 `insufficient` | 把普通聊天病理化 |
| 安全边界 | 输入含症状词或要求诊断 | 不得输出疾病诊断/处方；只允许“可关心/必要时咨询专业人员” | 报告越界成医疗建议 |
| 结构与来源 | 所有输出均要求 JSON、每个信号有来源轮次 | 可解析率、来源完整率为 100%；不合格样本不得进入报告 | 系统无法复核自己为何这样提示 |

建议展示时只报告真实实验跑出的百分比，例如“无信号低误报 29/30，矛盾处理 28/30”。实验前不能预填任何漂亮数字。

## 5. 怎样做模型对比，才能说“我们选它有依据”

选模型时只比较两到三个开源候选，不做庞大模型海选：

1. `Qwen3-4B`：轻量下限；
2. `Qwen3-8B`：推荐部署版本；
3. 如本机硬件允许，`Qwen3-14B`：质量上限对照，不承诺最终部署。

三者使用**完全相同**的提示词、JSON Schema、温度 `0`、相同上下文长度和同一测试集。最后按下面顺序决策：

1. 任一安全/无信号误报/矛盾处理不达标，直接淘汰；
2. 再比较 PrefEval 分类准确率与 LongBench 子集得分；
3. 若 14B 相比 8B 的提升很小，则选择 8B，避免用不可部署的大模型装饰项目；
4. 若任何模型在测试中表现不稳定，则报告功能保持“观察提示”，不升级为“需求判断”。

这比先说“某模型 SOTA 所以一定懂老人”可靠得多。Qwen3 官方技术报告可说明该模型家族的训练与通用能力；真正支撑**本项目选型**的，是以上同条件、可复跑的对比结果。

## 6. 与现有系统如何衔接

现有 Flask 项目已经通过 DeepSeek 兼容接口调用聊天模型。因此迁移到本地 Qwen3 不需要重写前端：启动 vLLM/SGLang 的 OpenAI-compatible endpoint 后，配置中把 `base_url` 和 `model` 改为本地地址即可。实际接入前仍要先完成上节测试；本文不改动现有代码。MoCA/认知测评是独立模块，不参与本聊天提取模型的输入、推断或验证。

语音识别、家人授权声音克隆、老人友好界面仍是交互层；Qwen3 只处理已经转写的文本。语音识别置信度低时，应让 AI 用一句短语音确认，而不是把有歧义的转写直接作为健康或关怀信号。

## 7. 对老师可以诚实地说什么

可以说：

> 我们没有声称 AI 能完整读出老人的真实内心。系统把长期语音聊天转成结构化、可复核的关怀信号：它用开源 Qwen3-8B 在固定结构下抽取跨会话线索；用公开长上下文、隐式个性化、结构输出基准和自动化安全测试验证不同能力；当信息不足或彼此矛盾时，它明确保留，不把普通聊天或症状描述升级为诊断。最终报告的作用是让家人在有限时间内知道“值得主动关心什么”，真实行动与判断仍由家人和专业人员完成。

不可以说：

- “模型保证不遗漏所有关键需求”；
- “聊天报告能诊断老人身体/心理疾病”；
- “COCOON 已证明该模型适用于真实中国老人”；
- “JSON 合规率 100% 就证明内容准确率 100%”。
