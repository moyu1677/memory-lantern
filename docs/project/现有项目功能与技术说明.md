# 忆路明灯：现有项目功能与技术说明

> 本文只解释 ZIP 中**已经存在的项目**做了什么、为什么做、用了什么技术。它不等于后续“老人—家人沟通桥梁”的新方向，也不把尚未实现的功能写成已完成。

## 1. 这个项目原本是什么

“忆路明灯”原本是一个面向老年人的综合型网页原型。它把几种能力放在同一个网站里：

- 老人做简短的认知相关任务；
- 老人可以文字或语音聊天；
- 家属、社区人员可以绑定老人并查看结果；
- 用户可以看健康知识、玩成语接龙；
- 管理员可以管理账户、知识文章和 RAG 文档。

简单说，原本的项目想做的是：

> **给老人一个能聊天、能做小任务、能获得日常建议的网页；同时让家人或社区人员了解老人完成任务的情况。**

它有很多功能，但当前最大的特点也是问题：这些功能大多是并列存在的，还没有围绕“老人和家人的沟通”形成一条完整主线。

---

## 2. 系统里有哪些人

系统有四种账户。

| 账户 | 目前可以做什么 |
| --- | --- |
| 老人 | 聊天、做短任务、查看历史、玩成语接龙、看健康知识、生成绑定码 |
| 家属 | 输入绑定码绑定老人、查看老人历史和报告、与共同绑定的社区人员留言、看知识中心 |
| 社区人员 | 与家属类似，也可提交知识文章供审核 |
| 管理员 | 管理用户、知识文章、RAG 文档和账户状态 |

当前绑定逻辑是：老人账户有一个绑定码；家属或社区人员拿到绑定码后即可建立关系。

## 3. 已有的主要功能

### 3.1 十道短任务与固定评分

老人可以开始一次“认知表现测试”。系统会从题库中随机组成 10 道题，总分 14 分，涉及七类内容：

| 内容 | 题目大意 |
| --- | --- |
| 即时记忆 | 记住少量词语或物品 |
| 延迟记忆 | 隔一段时间再回忆前面的内容 |
| 时间定向 | 年、月、日、星期等 |
| 注意力 | 简单数字或注意力任务 |
| 计算能力 | 简单生活计算 |
| 语言能力 | 复述或关键词表达 |
| 日常判断 | 常见生活安全情境 |

评分是确定性的：程序根据预设答案、关键词或标准答案直接计算，不依赖大模型。

任务完成后，系统保存：

- 得分和百分制分数；
- 七个维度的得分；
- 输入语言；
- 完成时间；
- 使用的题目编号。

**原本目的**：用一次短任务记录老人当次的任务表现，并根据薄弱维度提供日常练习建议。

**需要正确理解**：它不是医学量表，不能凭结果诊断老人是否健康。

### 3.2 固定规则报告

每次任务后，系统会生成“专属建议报告”。报告中有：

- 本次百分制结果；
- 每个维度的分数；
- 相对表现较稳定的维度；
- 优先练习的维度；
- 固定的一周参考安排；
- 日常健康建议和就医提醒；
- 推荐阅读的健康知识文章。

它看起来是个性化报告，但实际逻辑是：**根据本次分数中相对较弱的维度，从预先写好的建议中挑选内容。**

它还没有读取老人自然聊天内容、长期需求、家人关系或老人反馈，因此还不是我们后续讨论的“沟通桥梁”。

### 3.3 老人陪伴聊天

老人端有一个聊天页面，可进行两种模式的聊天：

| 模式 | 做什么 |
| --- | --- |
| 普通陪伴 | 使用 DeepSeek 进行日常聊天、陪伴性回复 |
| 知识问答 | 先从已审核健康知识中找资料，再让 DeepSeek 根据资料回答 |

系统还写了两层安全限制：

- 没有可靠资料时，不应装作知道；
- 出现明显紧急表达时，返回固定的紧急提示，而不是让模型随意回答。

目前聊天的主要目的仍是“陪伴”和“健康知识问答”，并不保存、整理成家属需求摘要。

### 3.4 三种语音输入方式

老人可以不用打字，使用语音。

| 语言 | 当前技术路径 |
| --- | --- |
| 普通话 | 浏览器自带 Web Speech API |
| 粤语 | 腾讯云语音识别 |
| 潮汕话 | 腾讯云语音识别 |

浏览器语音适合普通话；粤语、潮汕话会录音后上传，由服务器调用腾讯云识别，再把文字放回输入框。

这部分的初衷是降低老人打字负担，适配方言环境。

当前已验证的问题是：聊天页的语音转写完成后会自动发送；若语音用于短任务，会可能直接影响计分。因此后续必须改成“先显示文字、老人确认后再提交”。

### 3.5 家属与社区绑定、历史查看、留言

家属和社区人员可以输入老人绑定码。绑定后，目前可以：

- 看到老人完成过几次任务；
- 查看历史结果；
- 打开具体得分和专属报告；
- 与共同绑定同一位老人的家属/社区人员留言。

原本目的：让家庭和社区共同关注老人。

当前问题：绑定后家属可查看完整分数、维度和报告；系统还没有“老人单独授权什么能分享、家属只看摘要”的能力。

### 3.6 健康知识中心和 RAG 文档

系统内置健康知识文章，内容分给老人、家属、社区等不同人群。管理员还可以上传 PDF、DOCX、TXT、Markdown 等文档。

上传后的文档会被切成小段，建立本地检索片段。用户提问时，系统先找相近的知识片段，再把这些片段和问题一起交给模型组织答案。

原本目的：尽量让健康相关回答有资料来源，而不是完全依靠模型临时编写。

### 3.7 成语接龙

老人端有成语接龙小游戏：电脑出一个成语，老人用最后一个字接下去；支持打字、普通话、粤语和潮汕话输入，也有提示和朗读。

它的定位是轻松的语言娱乐，不属于前面的短任务测试。

### 3.8 管理后台

管理员可：

- 查看和启用/停用用户；
- 协助重置密码；
- 新建、编辑、审核知识文章；
- 上传、发布、停用、删除 RAG 文档；
- 重新建立知识检索片段。

## 4. 现有技术架构

```text
浏览器页面
    ↓
Flask 后端
    ├─ SQLite 数据库
    ├─ 固定题库与评分规则
    ├─ 固定报告生成规则
    ├─ DeepSeek 聊天与知识问答
    ├─ 腾讯云方言语音识别
    └─ PDF / DOCX 文档解析与本地检索
```

### 4.1 前端

- HTML 页面模板：Jinja2；
- 样式：原生 CSS；
- 页面交互：原生 JavaScript；
- 适老化设计：较大按钮、较大文字、语音入口、语音朗读。

这不是 React、小程序或手机 App，而是 Flask 渲染的网页。

### 4.2 后端

- 框架：Python Flask；
- 登录状态：Flask Session；
- 表单保护：CSRF Token；
- 权限：老人、家属、社区、管理员四种账户；
- 数据库：SQLite，使用 WAL 模式减少读写冲突。

### 4.3 大模型：DeepSeek

项目使用 OpenAI 兼容方式调用 DeepSeek。

DeepSeek 当前主要用于：

- 普通聊天；
- 基于知识库的回答；
- 组织更自然的文字回复。

DeepSeek **不参与**短任务评分和固定报告评分，因此当前的分数不是模型临时判断出来的。

### 4.4 语音识别

- 普通话：浏览器 Web Speech API；
- 粤语、潮汕话：浏览器录音 → Flask 接收音频 → 本地 `ffmpeg` 转码 → 腾讯云 WebSocket 识别；
- 识别失败时，用户可使用文字输入作为回退。

### 4.5 知识检索：现有 RAG

RAG 可以理解为“先找资料，再让模型回答”。

当前项目的 RAG 并没有使用我们前面讨论的向量隐空间；它采用本地分词、关键词和 n-gram 相似度来检索文章片段。找到最相关的片段后，再连同问题交给 DeepSeek。

这样做的优点是轻量、易部署；缺点是面对完全不同说法时，语义理解能力有限。

### 4.6 文档解析

- PDF：`pypdf`；
- DOCX：`python-docx`；
- 文本和 Markdown：直接读取；
- 上传文档后会计算内容哈希，避免重复导入。

## 5. 关键代码文件分别做什么

| 文件 | 作用 |
| --- | --- |
| `app.py` | Flask 入口、页面路由、登录、权限、聊天、语音、短任务接口 |
| `database.py` | 建表、账户、绑定、消息、知识文章、RAG 文档、任务记录的数据库操作 |
| `questions.py` | 十道短任务的组卷、预设答案、判分、七维度分数 |
| `reports.py` | 根据一次任务得分生成固定建议报告 |
| `rag.py` | 知识文章切分、检索、资料约束式模型回答 |
| `tencent_asr.py` | 调用腾讯云语音识别 |
| `idiom_game.py` | 成语接龙逻辑 |
| `knowledge_seed.py` | 内置健康知识文章 |
| `templates/` | 所有网页界面 |
| `tests/` | 功能、权限、报告、知识库自动化测试 |

## 6. 原项目目前能证明什么

它能证明：

- 系统能让不同角色登录并使用不同功能；
- 能完成固定短任务、评分、保存记录、生成报告；
- 能进行普通话/粤语/潮汕话的语音输入链路；
- 能让家属通过绑定关系查看信息；
- 能从资料库中检索内容，再组织健康知识回答；
- 在补齐 Windows 所需 `tzdata` 依赖后，78 项既有自动化测试可以通过。

它不能证明：

- 十道题可以诊断老人健康；
- 一次低分说明认知下降；
- 语音识别对真实方言老人一定准确；
- 家属目前只会看到经过老人确认的摘要；
- 聊天内容已经能自动识别老人需求。

---

## 7. 一句话总结

原项目已经是一个有基础功能的“老年数字陪伴与任务记录平台”。它的短任务、语音、聊天、绑定、知识库和后台都已经存在；我们后续要做的，不是从零造网站，而是把这些原本分散的功能收敛成真正能连接老人和家人的核心能力。
