# 忆路明灯：项目核心定位与产品定案

## 先给结论

项目不应被讲成“用十道题检测老人有没有认知问题”。这既不成立，也不是现有代码能够证明的事。

它应该被做成一个**会根据老人当下状态，把下一次日常练习变得更合适，并在老人允许时告诉家属怎样陪伴的轻量助手**。

最简单的一句话是：

> **老人说“今天有点累”，系统就把下一次练习变短、提示变多；老人同意后，家属只看到“明天可以怎么陪”，而不是分数和诊断。**

这才是“忆路明灯”要解决的具体问题：老人不因一次答不好而受挫，家属也不需要靠偷窥分数来判断怎样陪伴。

---

## 为什么现有方案还不够准确

当前代码已有“十道短题 → 分数 → 固定报告”。原先的改造方案提出“根据历史把下一次任务变难或变简单”。这一步需要改写：

**不能把用于记录表现的测试题，和用于日常练习的题混在一起。**

如果测试本身每次难度不同：

- 上次 80 分、下次 60 分不能直接比较；
- “历史趋势”会混入题目难度变化；
- 更容易让人误以为系统在评估甚至诊断老人；
- 老人也会把一次答不好理解成“我退步了”。

所以要把系统分成两条线：

```text
固定短任务（只记录本次表现，不下诊断）
                  ↓
          生成下一次练习卡
                  ↓
老人反馈：太难 / 太简单 / 今天疲劳
                  ↓
可调整的日常练习与陪伴方式
                  ↓
老人授权后，家属获得一条陪伴建议
```

固定短任务保持原有结构；真正变化的是**练习卡的时长、提示和陪伴方式**，不是测试的分数标准。

---

## 最终产品到底长什么样

### 老人看到的

1. 先做一次很短的任务；语音转文字后必须由老人确认，不能自动提交。
2. 结果页面不说“好/坏”或“风险”，只说“这次哪类任务更费劲”。
3. 系统给一张下一次练习卡，例如：
   - **练什么**：记住 3 个日常物品；
   - **做多久**：3 分钟；
   - **怎么做**：先看图片，再给首字提示；
   - **为什么**：今天选择了“有点累”，所以练习缩短、提示更多。
4. 老人可点“太难”“太简单”“今天疲劳”或“不想做”。这些不是扣分，而是告诉系统下一次怎样更舒服。
5. 老人可选择是否把一条简短建议分享给已绑定的家属。

### 家属看到的

家属不应看到完整分数、题目答案或医疗式判断，只在老人授权后看到一条可行动的话：

> “明天可陪她一起看大字日历 3 分钟；她今天觉得疲劳，先不要催促答题。”

家属要做的是陪伴，不是监测或给老人贴标签。

---

## 核心能力：只保留四件事

| 核心能力 | 用户能直接感受到什么 | 现有代码基础 |
| --- | --- | --- |
| 1. 固定任务记录 | 完成一次短任务，留下本次表现 | 已有 10 题、评分、历史记录 |
| 2. 练习卡生成 | 获得下一次“练什么、多久、怎样练、为什么”的卡片 | 现有固定报告可改造成输入 |
| 3. 反馈改变练习 | 点击疲劳或太难后，下一张卡确实变短、提示变多 | 需要新增 |
| 4. 授权式家属摘要 | 老人开关授权；家属只看到一条陪伴建议 | 已有绑定关系，需收紧权限 |

聊天、RAG、知识库、方言、成语游戏和后台都可以保留，但只能作为支撑。它们不再抢走项目主线。

---

## 规则要少，而且每条都能解释

只需要下面五条：

1. 记录少于 3 次：给 3 分钟的基础练习，不说趋势。
2. 最近几次同一类任务都较费劲：下次优先练这一类，但不把它称作能力下降。
3. 选择“太难”或“今天疲劳”：下一次缩短到 3 分钟，并增加提示。
4. 选择“太简单”：下一次可延长到 5 分钟或减少一个提示，但不改变固定任务的评分标准。
5. 未授权：家属看不到任何摘要；已授权：家属只看到陪伴建议，不看分数、原始答案或诊断性结论。

这些规则不是医学知识，也不是人工智能预测。它们是透明的产品规则：每个变化都能让老人看懂“为什么”。

---

## 项目要证明什么，不要证明什么

### 可以诚实证明

- 相同历史、反馈和授权状态，会稳定得到相同练习卡；
- 反馈会使下一张练习卡出现符合规则的变化；
- 未授权时家属无法取得摘要，授权后也只能取得摘要；
- 语音识别文本在确认前不会进入评分；
- 旧版“固定报告”与新版“可解释练习卡”在同一输入下有清楚区别。

### 绝不能声称

- 系统能诊断、筛查或检测认知障碍；
- 分数下降代表老人认知退化；
- 系统改善了认知能力；
- 少量内部测试证明真实老人都会喜欢或受益。

---

## 老人群体的 benchmark 应该测什么

不应给老人设置“必须完成多少题才合格”的 benchmark，更不应把项目自设分数当成医学基准。

应该测的是**系统有没有把事情做得更容易、更安全**：

| 检查对象 | 可验证的标准 |
| --- | --- |
| 可理解性 | 每张练习卡都说清“练什么、多久、为什么” |
| 可操作性 | 大按钮、文字输入回退、语音确认后再提交、可随时退出 |
| 不挫败 | 疲劳/太难会让下次更轻，而非被判定为失败 |
| 隐私 | 老人不授权时，家属摘要和完整报告均不可见 |
| 一致性 | 同一组输入重复运行，输出完全一致 |

这类检查能由系统测试和演示场景完成。若之后有自愿老人体验，只能补充“是否听懂、能否操作、是否感到压力”的可用性观察，不能把它包装成临床实验。

---

## 最终演示应该让老师看到的一件事

不要展示一堆菜单。只展示一个人、两个时刻：

```text
第一次：老人完成短任务 → 得到 5 分钟练习卡
老人点击“今天疲劳”
第二次：同一人得到 3 分钟、提示更多的练习卡
老人关闭授权 → 家属看不到摘要
老人开启授权 → 家属只看到一条陪伴建议
```

老师能在三分钟内看懂这件事，PPT、Poster 和摘要就都有了共同中心。

---

## 与现有文档和代码的关系

这份定案取代旧方案中“动态改变下一次测试难度”的表述；应统一改为“动态调整下一次练习和陪伴方式”。

现有代码中必须优先处理的事实是：语音文本会自动提交计分、绑定后能看完整历史、报告是固定规则、依赖清单漏了 `tzdata`、提交 ZIP 含密钥和数据。它们不是概念问题，而是这个核心产品能否安全成立的前提。
