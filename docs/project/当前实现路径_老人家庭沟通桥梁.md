# 忆路明灯：当前实现路径定稿

## 1. 我们现在到底做什么

**忆路明灯不是认知测试工具，也不是替家人照顾老人的机器人。**

它是一个帮助老人更自然地表达生活需要、再让家人在很短时间内理解这些需要的沟通桥梁。

> 老人和 AI 自然聊天；AI 在合适的时候帮助老人把一件生活小事说清楚；老人同意后，家人看到一张简短、有依据的关怀卡；家人自己决定怎样联系和行动。

系统不判断老人是否健康，不给老人打分，不要求老人填写问卷，也不替家人作决定。

---

## 2. 老人实际经历的过程

老人只需要像平常一样说话。

```text
老人自然聊天
    ↓
老人主动提到一件具体生活事情
    ↓
AI 顺着上下文温和追问一次
    ↓
老人说出这件事是否造成不便、自己希望怎样处理
    ↓
AI 询问是否愿意让已绑定家人知道
    ↓
老人同意后，生成家属关怀卡
```

示例：

```text
老人：阳台灯还没修。

AI：晚上用阳台会不会不太方便？

老人：晾衣服时看不清。下次儿子来让他顺便看看吧。

AI：我可以只记成“阳台照明不方便、希望下次顺便看看”，
    放进给儿子的摘要里，不放完整聊天。可以吗？

老人：可以。
```

如果老人说“不想谈”“不用告诉家人”，或者转移话题，AI 就停止，不生成卡片，也不继续追问。

---

## 3. 家人看到什么

家人不看完整聊天、原始录音、分数或健康标签，只看最多几张简短关怀卡。

```text
本周生活线索：阳台照明不方便。
老人意愿：希望下次来时顺便看看。
来源：老人已确认分享的聊天内容。
沟通切口：可以先问问“阳台灯后来修好了吗？”
```

这张卡不是命令家人做什么，而是让家人不用猜：老人最近真正提到什么、愿意让家人知道什么、可以怎样自然开口。

## 4. 系统内部怎么实现

### 4.1 不使用的技术

本版本不做：

- 每句话嵌入向量库；
- 隐空间用户画像；
- 向量距离直接判断需求；
- 自动诊断或健康评分；
- 问卷、标准答案、认知得分；
- 家人私聊读取或“猜测老人没有说过的事”。

### 4.2 只保留的核心技术

每一轮聊天结束后，模型只生成一张受限制的“会话需求卡”。

```json
{
  "category": "居家事务",
  "subject": "阳台照明",
  "polarity": "needs_help",
  "directness": "indirect",
  "evidence": "晾衣服时看不清",
  "share_confirmed": true
}
```

固定类别只有：居家事务、出行与生活安排、身体不适原话、家庭联系、社交与情感表达、兴趣与愿望、服务或物品、互动偏好。

`polarity` 必须明确区分：

- `needs_help`：愿意或需要协助；
- `declines_help`：明确不希望协助；
- `mentions_interest`：提到某人、某事或兴趣；
- `uncertain`：信息不够。

因此“想让家人来”和“不想麻烦家人来”不会被混为同一件事。

### 4.3 需求引导状态机

```text
无生活线索
    → 正常聊天，不问需求。

提到具体生活事实
    → 只允许一次上下文追问。

说出影响或个人想法
    → 询问是否愿意分享给家人。

确认分享
    → 生成家属卡。

拒绝、换话题、语音未确认
    → 停止，不分享，同一话题暂不再追问。
```

模型负责理解老人说的话；状态机负责控制何时问、何时停、何时允许分享。

## 5. 需要复用和新增的代码

### 复用现有代码

- 老人端聊天入口；
- 普通话、粤语、潮汕话语音转文字；
- 老人、家属账户和绑定关系；
- SQLite 数据库；
- Flask 页面和权限框架；
- 现有大模型调用入口。

### 只新增一个核心模块

新增 `needs_engine.py`：

```text
extract_session_card()   聊天文本 → 受限制的需求卡
validate_card()          检查原话、态度、类别是否一致
next_dialogue_action()   决定正常聊、追问一次、询问分享或停止
build_family_brief()     已授权需求卡 → 家属关怀卡
```

数据库只需保存：一次聊天是否确认、需求卡、分享授权、家属关怀卡。现有绑定关系仍然使用，但家属不能再直接看到完整测试历史或报告。

---

## 6. 必须满足的结果

实现完成后，必须能实际演示以下链路：

1. 老人自然提到一件生活事情；
2. AI 只顺着问一次，而不是连续盘问；
3. 老人表达影响和个人意愿；
4. 老人拒绝分享时，家属看不到任何内容；
5. 老人确认分享时，家属只看到一张有原话依据的关怀卡；
6. 家属看不到完整聊天、录音、分数和疾病判断；
7. “想/不想”“需要/不需要”等相反表达不会被混淆。

---

## 7. 最终边界

系统能做的是：让老人更容易表达，让家人更容易理解。

系统不能做的是：替老人说话、替家人行动、判断老人是否健康、从沉默中猜出需求。
