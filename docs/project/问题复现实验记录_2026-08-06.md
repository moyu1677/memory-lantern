# 忆路明灯：代码问题复现实验记录

**实验日期：2026-08-06**
**对象：`忆路明灯.zip` 中的源码脱敏审计副本**
**原则：不读取 `.env`、密钥、真实数据库或录音；不改动原始项目代码。**

## 1. 实验目的

本轮不是验证“功能是否大体可用”，而是专门复现已经发现的风险：

1. 语音识别文字是否未经老人确认就进入计分；
2. 家属绑定后是否能在没有老人单独授权的情况下看到完整测试信息；
3. 项目是否能只依赖 `requirements.txt` 在干净 Windows 环境运行；
4. 现有自动化测试是否能发现这些问题。

## 2. 结果总表

| 编号 | 实验 | 当前结果 | 判定 |
| --- | --- | --- | --- |
| E1 | 现有自动化功能与权限回归 | 补齐环境中的 `tzdata` 后，78/78 通过，23.39 秒 | 通过，但不覆盖下列风险 |
| E2 | 云端方言语音文字提交路径 | 识别文字写入输入框后，立即执行 `await sendMessage()` | 不通过 |
| E3 | 浏览器普通话语音文字提交路径 | 识别文字写入输入框后，立即执行 `sendMessage()` | 不通过 |
| E4 | 已绑定家属读取老人详情 | 实际 HTTP 请求：`/history/<id>` 返回 200，页面含 `14/14` | 不通过 |
| E5 | 已绑定家属读取老人报告 | 实际 HTTP 请求：`/history/<id>/report` 返回 200，页面展示百分制 `100` 分 | 不通过 |
| E6 | 反馈、授权和练习卡的数据存储 | `assessments`、`care_bindings` 两张现有表均无对应字段 | 当前尚未实现 |

## 3. 可复现证据

### E2 / E3：语音会绕过确认直接提交

静态路径检查显示：

```text
云端语音：input.value = data.text → await sendMessage()
浏览器语音：input.value = transcript → sendMessage()
```

对应源码为 `templates/index.html` 第 962–963 行和第 1015–1016 行。

这意味着 ASR 误识别、方言识别偏差或老人说错后，文字会直接进入当前认知任务的计分流程。正确的目标行为应是：文字先进入输入框，老人确认或修改后，再主动点击“提交”。

### E4 / E5：家属可看到完整信息

在隔离数据库中创建一名老人、一名家属和一条满分测试记录后，使用老人绑定码建立关系，再以家属会话访问：

```text
GET /history/<assessment_id>         → HTTP 200，页面含总分 14/14
GET /history/<assessment_id>/report  → HTTP 200，页面含本次百分制 100 分
```

数据库表结构也确认：

```text
assessments：无 feedback / consent / plan 字段
care_bindings：只有 elder_id、caregiver_id、created_at
```

所以当前“绑定码”实际等同于查看完整历史和报告的授权；系统没有老人逐次授权、没有家属摘要模式，也没有反馈或练习卡保存位置。

### E7：依赖清单不能支撑干净 Windows 环境

创建全新 Python 虚拟环境后：

```text
tzdata 已安装：False
ZoneInfo('Asia/Shanghai')：失败，退出码 1
```

源码在 `app.py` 使用 `ZoneInfo("Asia/Shanghai")`，但 `requirements.txt` 没有声明 `tzdata`。在本机干净环境中，这会使报告页和管理员用户页报错。

### E8：部署配置

静态检查确认以下内容仍在源码中：

```text
FLASK_SECRET_KEY 缺失时回退到 development-only-change-me
app.run(debug=True, port=5000)
```

它们不影响本地课堂演示的核心功能，但不能作为正式部署配置。

## 4. 这轮实验没有做什么

- 没有调用 DeepSeek 或腾讯云；
- 没有使用 ZIP 中的真实密钥、数据库或录音；
- 没有运行真实方言 CER、真实老人体验或临床相关测试；
- 没有改动源码、数据库结构或页面。

这些未测项目不能写成“已验证”。

## 5. 验收结论

现有核心流程在补齐 `tzdata` 后可以通过 78 项常规自动化测试；但上述 E2–E8 表明，测试套件尚未覆盖语音确认、授权摘要、依赖完整性和部署安全。后续修复应以本记录的 E2–E7 作为回归验收基线：修复后应分别变为“语音不自动提交”“未授权家属返回 403 或只见摘要”“干净环境可打开报告页”。
