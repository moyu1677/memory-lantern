# 代码结构与模块边界

## 总体原则

`app.py` 是稳定的 Flask 启动入口，负责 HTTP 路由、鉴权和业务模块编排。可复用算法、数据访问和外部服务代码放在 `memory_lantern` 包中，避免继续扩大单文件职责。

```text
浏览器 / API
     │
     ▼
app.py（路由、权限、会话、流程编排）
     │
     ├── assessment（题库、回答处理、评分、报告）
     ├── drawing（绘图辅助评分）
     ├── knowledge（知识库与 RAG）
     ├── games（成语接龙）
     ├── integrations（腾讯云 ASR）
     ├── core（国际化、研究展示）
     └── persistence（SQLite 数据访问）
```

## 目录职责

| 目录 | 职责 | 不应放入 |
| --- | --- | --- |
| `assessment` | 题目生成、答案清洗、安全规则、语义模型、语音派生指标、报告 | Flask 路由、云厂商密钥 |
| `drawing` | 绘图轨迹特征、实验模型加载与低置信度拒判 | 临床诊断结论 |
| `knowledge` | 审核内容检索、RAG 上下文构建 | 未审核医疗建议 |
| `games` | 成语接龙状态和规则 | 用户权限逻辑 |
| `integrations` | 第三方 API 协议封装 | 页面渲染 |
| `persistence` | 建表、迁移和查询 | HTML 与外部 API 调用 |
| `core` | 无明确业务归属的公共能力 | 大型业务流程 |

## 数据和实验

- `data/`：运行期 SQLite 与种子数据，本地数据库不提交；
- `ml_experiments/`：可独立运行的研究实验，不直接决定正式测试分数；
- `tests/datasets/`：本地公开数据集和生成清单，大文件不提交；
- `tests/benchmarks/`：需要人工准备环境或真实云服务的性能/识别测试；
- `tests/test_*.py`：不访问外网的自动化回归测试。

## 新功能放置规则

1. 先判断属于哪个业务模块；
2. 在模块内实现可测试函数或服务；
3. `app.py` 只调用该接口；
4. 在 `tests/` 添加离线测试；
5. 涉及环境变量时同步更新 `.env.example` 和配置文档；
6. 涉及用户文案时同步维护中英文版本。
